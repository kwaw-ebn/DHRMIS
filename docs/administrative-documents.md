# Administrative document register — 0.4.3

Open **Document register → Upload document** to file meeting minutes, incoming letters, outgoing letters, memos, circulars, reports, policies/guidelines or other administrative records. Upload PDF, JPEG, PNG, Word DOCX or Excel XLSX, up to 10 MB per file. For a multipage scan, use one PDF. Legacy DOC/XLS, encrypted Office packages and macro-enabled Office documents are unsupported; export a PDF copy instead.

Each entry records its subject/title, category, responsible office/unit, document or meeting date, received/sent/filed date, optional reference/file number, sender, recipient and notes. Incoming letters require a sender; outgoing letters require a recipient. Dates describe the filed record; storing an outgoing letter does not send it or establish delivery. Meeting uploads do not extract attendance, decisions or actions. The existing Correspondence register remains the place for tracked workflow tasks; this register stores uploaded copies. Confidential individual staff documents should use Personnel documents.

Search covers title, reference, sender and recipient. Filter by category, office/unit and document date. Results are paginated and can be downloaded through authenticated, short-lived links. Search does not extract or index file contents. Entries and files are immutable: archive an incorrect/superseded entry with a reason, then upload the corrected copy. The original private file and audit history are retained. Archiving hides it from the register; an already issued link can remain usable for up to 60 seconds.

## Access

HR can file and read records across the district. Heads can upload only within their organizational subtree. The default access is HR/Director plus the uploader, within the uploader's current unit scope. Optional **Authorized unit management** visibility allows scoped management users who already have access to that record's unit. It does not publish files to ordinary employees. Heads can archive only their own uploads; HR can archive any visible administrative record. Directors can read/download but cannot upload/archive. Employee, technical administrator and auditor accounts cannot access this register, including its titles or counts. Existing personnel-file permissions are unchanged.

The register uses the existing private object storage. Object keys and checksums are not returned in metadata listings. PDFs and images reuse the roster upload checks; image camera metadata is stripped. Office files must have the expected DOCX/XLSX package structure; archive sizes/counts, encryption, CRC failures and macro indicators are checked before accepting them. Office files retain their original contents and metadata. These checks are not a malware scan. Downloads are attachments. Access, uploads, downloads and archives are audited. Failed metadata commits attempt private-file cleanup.
